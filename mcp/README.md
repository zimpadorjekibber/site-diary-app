# Site Diary MCP — साइट का हिसाब Claude से पूछिए

अपनी साइट का डेटा Claude से सीधे सवाल-जवाब में पूछने के लिए। जैसे:

> "आज साइट पर कितना खर्च हुआ?"
> "रमेश का कितना बकाया है?"
> "इस महीने डीज़ल पर कितना गया?"
> "कल कौन-कौन गैरहाजिर था?"

और लिखवा भी सकते हैं:

> "विकिल अहमद की आज हाजिरी लगा दो"
> "नूर को 500 नकद दिए, लिख दो"
> "राजू नाम का मेसन हेल्पर जोड़ो, 550 दिहाड़ी"

**मिटाने वाला कोई tool नहीं है** — न कारीगर हटाने का, न हिसाब साफ़ करने का। एक ग़लत
समझे गए वाक्य से डायरी उजड़ने का ख़तरा मोल लेने लायक नहीं; वो काम ऐप में हैं, जहाँ
पूछकर होते हैं।

सिर्फ़ पढ़ने तक सीमित रखना हो तो `SITE_DIARY_READONLY=1` लगा दीजिए — तब लिखने वाले
tools दिखेंगे ही नहीं।

---

## सेट अप

### 1. अपनी Site ID देखें

ऐप में **⚙️ Settings → 🛠️ उन्नत सेटिंग्स → 🔑 आपकी साइट आईडी** — वहाँ 📋 कॉपी बटन भी है।
`site-XXXX-XXXX` जैसी दिखेगी।

### 2. Claude में जोड़ें

**Claude Code** में:

```bash
claude mcp add site-diary --env SITE_DIARY_SITE_ID=site-XXXX-XXXX -- node D:/MyProjects/site-diary-app/mcp/server.js
```

**Claude Desktop** में `claude_desktop_config.json` खोलकर:

```json
{
  "mcpServers": {
    "site-diary": {
      "command": "node",
      "args": ["D:/MyProjects/site-diary-app/mcp/server.js"],
      "env": { "SITE_DIARY_SITE_ID": "site-XXXX-XXXX" }
    }
  }
}
```

बस। Claude को नए सिरे से खोलिए और पूछना शुरू कीजिए।

## क्या-क्या पूछ सकते हैं

| Tool | किस काम का |
|---|---|
| `site_summary` | आज का कुल खर्च, हाजिरी, डायरी लिखी या नहीं |
| `list_workers` | कौन-कौन काम पर है, किस ट्रेड में, क्या दर |
| `worker_ledger` | किसी एक कारीगर का कमाया, दिया, बकाया |
| `attendance` | किसी तारीख की पूरी हाजिरी |
| `muster_roll` | पूरे महीने का रजिस्टर |
| `list_transactions` | लेन-देन — तारीख, प्रकार या कारीगर से छानकर |
| `spend_report` | किसी अवधि का खर्च, प्रकार और ट्रेड के हिसाब से |

### लिखने वाले

| Tool | किस काम का |
|---|---|
| `add_worker` | नया कारीगर जोड़ें (दिहाड़ी या ठेका) |
| `mark_attendance` | किसी एक की हाजिरी — पूरा दिन / आधा / गैरहाजिर, ओवरटाइम सहित |
| `mark_all_present` | सबकी हाजिरी एक साथ (जो पहले से आधा दिन/गैरहाजिर हैं, वे नहीं छिड़ते) |
| `add_expense` | खर्च या पेशगी लिखें |
| `update_worker` | दर, फ़ोन, ट्रेड बदलें — या ठेके की नाप भरें |

कारीगर का नाम अधूरा भी चलेगा ("रमेश" काफ़ी है)। दो नाम मिलते-जुलते हों तो यह पूछ लेगा
कि किसका मतलब है, अंदाज़ा नहीं लगाएगा।

## यह काम कैसे करता है

```
Claude  →  mcp/server.js  →  Firestore REST  →  site_diaries/<आपकी site id>
                  ↓
           src/storage.js  ← ऐप वाली ही गणना
```

हिसाब लगाने का कोड **दोबारा नहीं लिखा गया** — `server.js` ऐप के अपने `Store` को ही
क्लाउड से आए डेटा के इर्द-गिर्द बनाता है। इसलिए यहाँ जो आँकड़ा मिलेगा, ठीक वही ऐप की
स्क्रीन पर दिखता है। अलग से गणना लिखने पर दोनों में फ़र्क़ आना तय था — इस प्रोजेक्ट में
पहले यही गड़बड़ हो चुकी है (एक ही कारीगर का बकाया दो स्क्रीनों पर दो अलग दिखता था)।

डेटा क्लाउड से आता है, इसलिए **ऐप में क्लाउड बैकअप चालू होना ज़रूरी है** — वरना फ़ोन का
ताज़ा हिसाब यहाँ नहीं पहुँचेगा। एक सवाल के दौरान डेटा 15 सेकंड के लिए cache होता है,
ताकि कई tools एक ही तस्वीर देखें।

### लिखते वक़्त क्या ध्यान रखा गया है

हर बदलाव **Firestore transaction** में होता है। यानी अगर उसी पल फ़ोन ने भी कुछ सेव
किया, तो बदलाव नई हालत पर दोबारा लगाया जाता है — किसी का काम मिटता नहीं।

⚠️ **पर एक बात:** असली मालिक फ़ोन है। अगर फ़ोन में कोई ऐसा बदलाव पड़ा है जो अभी क्लाउड
तक नहीं पहुँचा, और आप यहाँ से कुछ लिख दें, तो फ़ोन अगली बार अपनी copy ऊपर चढ़ा देगा और
यहाँ का बदलाव मिट जाएगा। इसलिए यहाँ से कुछ लिखने के बाद **फ़ोन पर ऐप एक बार खोल लीजिए**
— तब वो नीचे आ जाएगा और दोनों एक हो जाएँगे।

### सुरक्षा

ऐप में login नहीं है; site id ही उसकी सुरक्षा है ([`firestore.rules`](../firestore.rules)
देखें)। इसलिए **site id को password की तरह सँभालें** — जिसके पास वो है, वो साइट का
हिसाब पढ़ सकता है।
